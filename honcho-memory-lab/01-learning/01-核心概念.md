# 01 — 核心概念

> Workspace / Peer / Session / Message / Conclusions 詳解

---

## Workspace（工作空間）

- 最頂層的命名空間，隔離所有資源
- 每個 Workspace 包含自己的 Peers、Sessions、Messages、Conclusions
- 不同 Workspace 的資料完全隔離（schema 層強制隔離，不可能跨 workspace 洩漏）
- 建立方式：`POST /v3/workspaces` 或 SDK `Honcho(workspace_id="my-app")`
- 一個應用通常用一個 Workspace

**使用情境**：
- 一個產品用一個 Workspace
- 測試環境用 `test-xxx` Workspace，不汙染 production

---

## Peer（參與者）

- Workspace 內的任何「人或 AI agent」
- 可以是使用者（human），也可以是 AI（assistant、agent）
- Peer 是 Honcho 建立心理模型的對象
- 每個 Peer 有自己的 representation（結論集合）

**重要**：Honcho 對每對 `(observer, observed)` peer 建立一個 Collection。
- `observer == observed`：自我認知（AI 的自我記憶）
- `observer A, observed B`：A 對 B 的認知（AI 對使用者的模型）

**建立方式**：

```python
user = honcho.peer("user-alice")
assistant = honcho.peer("assistant-claude")
```

---

## Session（會話）

- 一次對話的上下文容器
- 可包含多個 Peers（多人對話）
- 每個 Session 獨立，但同一個 Peer 跨 Session 的記憶會被整合

**Session 與 Peer 的關係**：
- Peer 是「人」，Session 是「這次對話場景」
- 同一個 user Peer 可以在 100 個 Session 裡出現
- Honcho 會跨所有 Session 整合這個 user 的記憶

**建立方式**：

```python
session = honcho.session("session-2024-01-15-morning")
session.add_peers([user, assistant])
```

---

## Message（訊息）

- 對話中的單一訊息單位
- 可以是對話（user ↔ assistant），也可以是任意資料輸入
- 一次可批次上傳最多 100 則 message
- 每則 message 有 `role`（哪個 peer 發送）和 `content`

**建立方式**：

```python
messages = [
    user.message("我最近在做一個財務 app"),
    assistant.message("聽起來很有趣，有什麼特別的功能嗎？"),
]
session.add_messages(messages)
```

**重要**：訊息寫入後，Deriver 會在**背景**處理。不是立即可查詢。
需要等待處理完成才能透過 Dialectic 查詢結果。

---

## Conclusions（結論）

- Honcho 從 Messages 萃取的知識單位
- API 層稱 "conclusions"，程式碼內部稱 "observations"
- 存在 Collection（vector store）裡，以 (observer, observed) pair 為 key

**三種結論**：

| 類型 | 來源 | 說明 |
|------|------|------|
| Explicit | Deriver | 對話中直接提到的事實 |
| Deductive | Dreamer / Deriver | 從事實推論出的洞察 |
| Inductive | Dreamer | 跨多個事實的歸納推論 |

**查詢方式**：

```python
# 語義搜尋結論
results = client.conclusions.query(
    workspace_id="my-app",
    peer_id="user-alice",
    query="工作壓力",
    top_k=5
)
```

---

## Peer Paradigm（Peer 典範）

Honcho 的核心設計：人和 AI 都是 Peer。

好處：
- 支援多人對話（multi-peer session）
- AI 可以有自己的 representation（自我記憶）
- 可設定誰觀察誰（observe settings）

```
Session 內：
  user-peer  ← observe → assistant-peer
      ↓                       ↓
 [user 的結論]           [assistant 的結論]
```

## 術語對照表

| 舊名 | 新名 | 說明 |
|------|------|------|
| App | Workspace | 頂層命名空間 |
| User | Peer | 任何參與者 |
| observation (code) | conclusion (API) | 萃取的知識單位 |
